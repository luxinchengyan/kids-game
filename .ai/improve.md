# 当前项目审查与改进建议

## 审查前提

- 当前项目的产品入口年龄已调整为 `2-15岁`。
- 但现有课程、玩法、成长路径和首页叙事仍主要围绕 `3-6岁` 或 `4-8岁` 设计，系统尚未真正升级为覆盖 `2-15岁` 的成熟商业产品。
- 因此，本次 review 重点不是“功能多不多”，而是“目标用户、内容供给、学习机制、增长与交付是否形成闭环”。

## 一、最高优先级问题

### 1. 目标用户年龄扩大了，但课程分层体系没有同步重构

- 产品文档原始定位仍以 `3-6岁` 为核心，[ai/PRD.md](/home/luxincheng/github/kids-game/ai/PRD.md:10) [ai/PRD.md](/home/luxincheng/github/kids-game/ai/PRD.md:13)。
- 首页成长阶段仍只拆到 `3-4岁 / 4-5岁 / 5-6岁`，[src/data/homeLearningJourney.ts](/home/luxincheng/github/kids-game/src/data/homeLearningJourney.ts:128)。
- 实际课程注册年龄大量集中在 `4-8岁`、`5-10岁`，例如拼音主线 [src/games/pinyin/index.ts](/home/luxincheng/github/kids-game/src/games/pinyin/index.ts:17)、扩展学科 [src/games/subjects/index.ts](/home/luxincheng/github/kids-game/src/games/subjects/index.ts:7)、AI 打字 [src/games/typing/index.ts](/home/luxincheng/github/kids-game/src/games/typing/index.ts:10)。

问题：
- `2-3岁` 用户缺少专门的感知型、亲子陪练型、低语言负担内容。
- `9-15岁` 用户缺少更高阶的目标、难度、成就体系与身份表达，现有 UI 与题型会显著幼龄化。
- 同一首页叙事同时服务低幼儿童与初中前后用户，产品心智会失焦。

建议：
- 先明确是“单产品多年龄层”，还是“儿童启蒙主产品 + 高龄扩展模块”。
- 若坚持 `2-15岁`，至少拆成 4 个产品层：`2-3`、`4-6`、`7-10`、`11-15`。
- 每层都要独立定义：核心目标、交互形式、反馈密度、奖励语言、家长价值。
- 在系统层面增加年龄段路由，不同年龄默认进入不同主页、课程包和视觉语言。

### 2. 内容边界膨胀过快，已经超出 MVP 和品牌聚焦能力

- README 既写拼音/数学/英语/传统文化，又加入地理、历史、化学、物理、生物和 AI 打字 [README.md](/home/luxincheng/github/kids-game/README.md:13)。
- 扩展学科入口已经注册到历史、化学、物理、生物、AI、百科六大主题 [src/games/subjects/index.ts](/home/luxincheng/github/kids-game/src/games/subjects/index.ts:7)。
- PRD 的 MVP 仍以首页、拼音、数学、基础激励和家长中心为主 [ai/PRD.md](/home/luxincheng/github/kids-game/ai/PRD.md:207)。

问题：
- 品牌主张不够尖锐，用户很难第一眼知道“这个产品到底最擅长什么”。
- 内容广度远超内容深度，容易出现“看起来很丰富，实际每条线都不够强”。
- 对儿童教育产品来说，范围越大，审核、安全、教研和持续更新成本越高。

建议：
- 短期收敛到 1 条主线能力包 + 1 条差异化副线。
- 推荐主线：`拼音 + 数学 + 英语启蒙`。
- 推荐副线：`故事/传统文化`，因为更适合建立品牌情感识别。
- 地理/历史/科学/AI 等扩展模块应降级为二期或会员扩展，而不是与主课程同权。

### 3. 激励系统的概念完整，但核心闭环并未真正落地

- PRD 中有签到、宠物、成就、里程碑、家长认证等完整激励塔 [ai/PRD.md](/home/luxincheng/github/kids-game/ai/PRD.md:154)。
- 首页直接展示签到和里程碑入口 [src/pages/HomePage.tsx](/home/luxincheng/github/kids-game/src/pages/HomePage.tsx:69)。
- 但 `useRewardStore.checkIn()` 目前为空实现，里程碑清理也是空函数 [src/stores/useRewardStore.ts](/home/luxincheng/github/kids-game/src/stores/useRewardStore.ts:56)。

问题：
- 用户可见承诺与真实系统能力不一致，会伤害家长信任。
- 激励反馈缺少“可持续目标”，容易沦为 UI 装饰。
- 奖励系统与学习结果、复习计划、成长报告之间耦合度不够。

建议：
- 先只保留 3 个真实可验证的激励环：`学习完成`、`连续学习`、`阶段解锁`。
- 所有首页展示的奖励模块必须有真实状态源、完成条件和回收逻辑。
- 奖励不能只发星星，要绑定“下一步可做什么”，例如：解锁复习关、故事章节、家长报告卡。

### 4. 学习科学理论写得多，但没有形成可验证的教学策略系统

- PRD 列出了遗忘曲线、ZPD、多元智能、操作性条件反射、自我决定理论、心流等一整套理论 [ai/PRD.md](/home/luxincheng/github/kids-game/ai/PRD.md:57)。
- `useGameStore` 里确实有简化版 SM-2 复习逻辑 [src/stores/useGameStore.ts](/home/luxincheng/github/kids-game/src/stores/useGameStore.ts:94)。

问题：
- 理论数量过多，但缺少“每个理论具体影响了哪一条产品决策”的映射。
- 目前更像“理论罗列”，不是“教学系统设计”。
- 对 `2-15岁` 来说，同一套遗忘节奏、反馈密度和认知负荷策略不能通用。

建议：
- 每个年龄层只保留 3 个核心教研机制，不要全都要。
- 推荐最低可落地教学闭环：
  - `学前低龄`：示范 -> 模仿 -> 立即强化 -> 短时复现
  - `小学中段`：讲解 -> 练习 -> 纠错 -> 间隔复习
  - `高龄扩展`：目标设定 -> 自主练习 -> 反思复盘 -> 阶段挑战
- 把理论从 PPT 语言改成系统参数：题量、节奏、提示次数、纠错形式、复习间隔。

## 二、重要问题

### 5. 年龄录入能力已放宽，但用户分发与推荐逻辑没有升级

- 创建档案页现在允许修改年龄，但系统默认 child、试用 child、课程推荐多数仍按低龄假设设计 [src/pages/SetupChildPage.tsx](/home/luxincheng/github/kids-game/src/pages/SetupChildPage.tsx:128) [src/App.tsx](/home/luxincheng/github/kids-game/src/App.tsx:102)。
- `getRecommendedThemeHub` 的推荐逻辑依赖各主题自身 `minAge/maxAge`，而这些范围仍大量停留在 `4-8` 左右 [src/games/registry.ts](/home/luxincheng/github/kids-game/src/games/registry.ts:168)。

问题：
- `2岁` 注册后可能仍被送入不合适的符号化课程。
- `12-15岁` 注册后可能被推荐幼龄主题中心，导致即时流失。

建议：
- 新增 `userSegment` 概念，注册后先分层，再推荐课程。
- 推荐逻辑不要只看 `minAge/maxAge`，还要看 `认知阶段`、`课程目标`、`历史表现`。

### 6. 家长价值主张还不够强，难以支撑商业化

- PRD 把家长定义为关键伙伴，强调放心、省心、看得见效果 [ai/PRD.md](/home/luxincheng/github/kids-game/ai/PRD.md:42)。
- 但当前系统更多展示孩子端玩法，家长端的数据价值仍偏浅。

问题：
- 家长付费不为“游戏多”，而为“规划感、效果感、陪伴效率”。
- 如果家长端没有周报、弱项、学习建议、节奏控制、目标完成率，商业闭环会很弱。

建议：
- 家长端优先做 4 张高价值卡：
  - 本周学习时长与完成率
  - 3 个优势点
  - 2 个待巩固点
  - 下周建议计划
- 所有报告要能回答家长最关心的 3 个问题：有没有学、学得怎么样、下一步怎么学。

### 7. SMART 原则没有真正进入任务系统

- 当前每日任务系统以完成次数、连续正确和探索数为主 [src/stores/useDailyQuestStore.ts](/home/luxincheng/github/kids-game/src/stores/useDailyQuestStore.ts:33)。

问题：
- 有 S 和 M，但 A/R/T 仍弱。
- 任务多数是平台视角，不是孩子或家长视角。
- 对不同年龄、不同弱项没有明显个性化。

建议：
- 每日任务改成 `一个主目标 + 一个复习目标 + 一个探索目标`。
- 示例：
  - `今天认会 2 个新拼音`
  - `复习昨天错过的 3 个知识点`
  - `用一句话讲给爸爸妈妈听`
- 让任务可被家长观察和验证，而不是只在系统里结算。

### 8. 纠错设计还不够“教学化”

- 通用考试系统主要关注答题、反馈、结果和计时 [src/games/common/ExamSystem.tsx](/home/luxincheng/github/kids-game/src/games/common/ExamSystem.tsx:1)。

问题：
- 错误后的处理更偏“答题反馈”，而不是“诊断错误类型 -> 给出更合适的支架”。
- 对儿童来说，“为什么错”比“错了没”更重要。

建议：
- 每道题至少区分 3 类错误：粗心、混淆、不会。
- 对应 3 类纠错：
  - 粗心：再看一次关键线索
  - 混淆：并排比较易混项
  - 不会：退回前置任务
- 让纠错变成新的学习入口，而不是一条提示语。

## 三、中长期结构问题

### 9. 视觉与语气目前更适合低幼，不适合 11-15 岁

- 设计语言整体偏“可爱、夸张、童话、拟人” [ai/DESIGN.md](/home/luxincheng/github/kids-game/ai/DESIGN.md:10)。
- 这对 `2-6岁` 很合理，但对 `11-15岁` 会快速产生羞耻感和排斥感。

建议：
- UI 至少拆成两套主题语言：
  - `儿童主题`：故事化、角色化、高反馈
  - `成长主题`：任务化、成就化、偏工具感
- 高龄层要减少幼态词汇、表情轰炸和“宝宝化”语言。

### 10. 账户注册年龄和课程适龄范围应明确区分

- 创建档案页和后端年龄是“允许注册范围”。
- `minAge/maxAge` 是“课程适配范围”。

建议：
- 这两个概念必须在产品和代码里分离。
- 不建议因为目标人群扩大到 `2-15岁`，就把所有游戏课程年龄上限一起强行改到 `15`。
- 正确做法是：先扩大账户体系，再逐步补齐课程分层。

## 四、建议的产品重构路线

### Phase 1：先把产品说清楚

- 明确北极星人群，到底主打 `2-6岁启蒙`，还是 `2-15岁成长平台`。
- 重写一句话定位、首页首屏和 App Store 文案。
- 把非核心学科全部归类为“拓展模块”。

### Phase 2：重做年龄分层

- 建立 `2-3 / 4-6 / 7-10 / 11-15` 四层结构。
- 每层定义课程包、题型、会话时长、奖励语言、家长报告格式。

### Phase 3：重做学习闭环

- 统一为：
  - `今日目标`
  - `主线学习`
  - `纠错强化`
  - `间隔复习`
  - `家长回看`

### Phase 4：再做增长与商业化

- 分享、邀请、节日活动、宠物养成都应建立在“孩子真的学到了”和“家长真的看见价值”之后。
- 否则增长只会放大留存问题。

## 结论

- 当前项目最强的地方是：主题丰富、文档意识强、游戏化表达积极、已经有课程化和成长化的雏形。
- 当前项目最大的问题不是“功能不够多”，而是“目标用户、课程范围、教研机制、激励系统、商业化价值没有被同一个清晰战略约束住”。
- 把用户入口年龄扩展为 `2-15岁` 可以做，但这会让现有分龄、UI、课程和学习机制的问题更加明显。
- 现阶段最优策略不是继续横向加内容，而是先完成 `分龄重构 + 主线聚焦 + 教学闭环 + 家长价值闭环`。
